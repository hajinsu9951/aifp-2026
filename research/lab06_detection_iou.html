확률과 넓이의 비로 열어 보기

6회차에서 객체 탐지 모델은 사진 속 음식마다 상자와 이름과 신뢰도를 붙여 주었습니다. 그 숫자들은 어디서 나왔고, 겹친 상자는 어떻게 정리되며, 모델이 ‘맞혔다’는 것은 무엇을 뜻할까요? 이 페이지는 지수함수(소프트맥스), 사각형의 넓이(IoU), 정렬과 제거(NMS), 비율(정밀도·재현율)로 그 과정을 손으로 계산하고 직접 조작하는 실습판입니다. 모든 계산은 브라우저 안에서 일어나며, 급식판 그림과 상자 좌표는 수업용으로 만든 가상의 값입니다.

① 점수를 확률로 — 소프트맥스 계산기

모델은 상자 하나를 보고 먼저 음식 종류마다 점수(로짓, z)를 냅니다. 점수는 음수도 되고 합도 제각각이라 그대로는 확률이 아닙니다. 소프트맥스는 pi = ezi/T ÷ Σ ezj/T 로 점수를 0과 1 사이, 합이 1인 값으로 바꿉니다. 화면에 뜨는 ‘계란말이 0.88’의 0.88이 바로 이 값입니다. 슬라이더로 점수와 온도 T를 바꾸며 표의 각 열을 손계산과 맞춰 보세요.

점수 z (모델의 마지막 층 출력)

확률 p (막대) · 빨간 선 = 신뢰도 임계값

같은 계산을 코드로

# 단계 ④ 코드로 옮기기 — 코랩에서 그대로 실행해 손계산과 비교
import math
z = [2.0, 1.0, 0.1] # 밥, 국, 김치의 점수
T = 1.0 # 온도
e = [math.exp(v / T) for v in z]
s = sum(e)
p = [v / s for v in e]
print([round(v, 3) for v in e], round(s, 3))
print([round(v, 3) for v in p], sum(p))

관찰할 것

  1. 왜 지수함수인가 · ez는 언제나 양수여서 음수 점수도 확률로 바꿀 수 있고, 점수가 1 커질 때마다 약 2.718배가 되어 1등을 더 도드라지게 합니다. ‘그냥 나누기’ 열과 비교해 보세요.
  2. 모든 점수에 같은 수를 더해도 확률은 그대로입니다. ez+c = ec·ez에서 ec가 분자·분모에서 약분됩니다. 확률을 정하는 것은 점수의 차이입니다.
  3. 온도 T · T가 작으면 1등이 거의 1에 가까워지고(자신만만), T가 크면 확률이 고르게 퍼집니다(망설임). 점수 순서는 T와 관계없이 그대로입니다.
  4. 신뢰도 임계값 · 탐지 프로그램은 보통 가장 큰 확률이 임계값 이상일 때만 상자를 화면에 남깁니다.

② 두 상자는 얼마나 겹치나 — IoU 손계산

상자는 왼쪽 위 꼭짓점 (x1, y1)과 오른쪽 아래 꼭짓점 (x2, y2) 네 수로 저장됩니다. 이미지 좌표는 y가 아래로 갈수록 커집니다. IoU(Intersection over Union)는 겹친 넓이 ÷ 합친 넓이입니다. 상자 안쪽을 끌면 옮겨지고, 모서리의 작은 네모를 끌면 크기가 바뀝니다(눈금에 맞춰 정수로 움직입니다).

상자 A · 상자 B · 칠해진 부분 = 교집합 · 점선 = 교집합을 정하는 max/min 선
함정 · max(0, …) 빼고 계산하기

같은 계산을 코드로

def iou(a, b):
# a, b = (x1, y1, x2, y2)
ix1, iy1 = max(a[0], b[0]), max(a[1], b[1])
ix2, iy2 = min(a[2], b[2]), min(a[3], b[3])
inter = max(0, ix2 - ix1) * max(0, iy2 - iy1)
area_a = (a[2] - a[0]) * (a[3] - a[1])
area_b = (b[2] - b[0]) * (b[3] - b[1])
return inter / (area_a + area_b - inter)
print(iou((2, 1, 6, 4), (4, 2, 8, 6))) # 0.1666...

관찰할 것

  1. 교집합의 왼쪽 끝은 두 왼쪽 끝 중 더 오른쪽(max), 오른쪽 끝은 두 오른쪽 끝 중 더 왼쪽(min)입니다. 위·아래도 같습니다.
  2. 합집합 넓이를 직접 세지 않고 A + B − 교집합으로 구합니다. 겹친 부분을 두 번 셌기 때문입니다(포함-배제).
  3. 함정 · 두 상자가 떨어져 있으면 폭과 높이가 음수가 됩니다. 둘 다 음수면 곱이 양수가 되어 ‘겹친 넓이’가 생겨 버립니다. 그래서 max(0, …)가 꼭 필요합니다.
  4. 함정 · 똑같이 한 칸 어긋나도 작은 상자는 IoU가 크게 떨어지고, 큰 상자는 조금만 떨어집니다. 작은 물체일수록 ‘맞혔다’ 판정을 받기 어렵습니다.

③ 이 상자는 맞힌 것인가 — IoU 임계값으로 정답 판정

급식판에는 실제 물체 6개(흰 점선, 정답 상자)가 있고 모델은 상자 11개(A~K)를 냈습니다. 예측 상자는 신뢰도가 높은 것부터 차례로, 같은 종류의 아직 짝이 없는 정답 상자와 IoU를 재어 IoU ≥ 임계값이면 TP 맞힘, 아니면 FP 헛짚음으로 판정합니다. 짝을 찾지 못한 정답 상자는 FN 놓침입니다. 표의 줄이나 그림의 상자를 눌러 고르고, 고른 예측 상자를 끌어 옮겨 보세요.

상자 이름 보기
흰 점선 = 정답 상자 · 초록 = TP · 빨강 = FP · 노란 굵은 선 = 고른 상자 · 칠해진 부분 = 고른 상자와 짝 후보의 교집합
판정 이유 네 가지
  • 위치 부정확 · 종류는 맞지만 IoU가 임계값보다 작음
  • 중복 · 같은 물체를 이미 더 높은 신뢰도의 상자가 맞혔음 (NMS가 지워야 할 상자)
  • 종류 틀림 · 상자 위치는 맞지만 이름이 다름
  • 없는 물체 · 겹치는 정답 상자가 아예 없음
생각해 볼 것
  • IoU 임계값 0.5는 널리 쓰이는 약속일 뿐 자연법칙이 아닙니다. 급식 칼로리 계산처럼 위치가 중요하다면 몇이 알맞을까요?
  • 밥 B(신뢰도 0.71)는 IoU가 0.667로 충분히 높은데도 FP입니다. 왜일까요?

④ 겹친 상자 정리 — NMS를 한 단계씩

모델은 같은 음식에 상자를 여러 개 내는 일이 흔합니다. NMS(Non-Maximum Suppression, 비최대 억제)는 ① 신뢰도 순으로 정렬 → ② 가장 높은 상자를 남김 → ③ 그 상자와 같은 종류이면서 IoU가 임계값보다 큰 상자를 지움 → ④ 남은 상자로 반복합니다. ‘다음’을 누를 때마다 한 단계씩 진행되고, 지금 실행 중인 줄이 코드와 기록에 강조됩니다.

노란 굵은 선 = 이번에 남긴 상자 · 하늘색 = 비교 중인 상자 · 초록 = 확정 · 흐린 회색 = 지워진 상자
함정 · 붙어 있는 두 물체계란말이 두 조각은 실제로 겹쳐 놓여 있어 F와 G의 IoU가 0.344입니다. 임계값을 0.3으로 낮추면 NMS는 G를 ‘F의 중복’으로 보고 지웁니다. 실제로는 다른 물체인데도 말입니다. 반대로 임계값을 높이면 진짜 중복(밥 B, 국 D)이 살아남습니다. 하나의 숫자로 두 가지 실수를 동시에 막을 수는 없습니다.
생각해 볼 것
  • NMS는 같은 종류끼리만 비교했습니다. 계란말이 F 위의 ‘김치 H’는 왜 지워지지 않았을까요? 종류를 무시하고 비교하면 무엇이 달라질까요?
  • 급식 사진에서 상자들이 많이 겹치는 상황(반찬이 붙어 있는 식판, 겹쳐 쌓인 우유)에서는 임계값을 어떻게 정해야 할까요?

⑤ 많이 찾을까, 정확히 찾을까 — 정밀도와 재현율

정밀도 = 맞힌 상자 ÷ 화면에 남긴 예측 상자 (TP ÷ (TP + FP)), 재현율 = 맞힌 상자 ÷ 실제 물체 (TP ÷ (TP + FN)). 신뢰도 임계값을 올리면 자신 있는 상자만 남아 정밀도는 오르지만, 자신 없던 진짜 물체를 놓쳐 재현율은 내려갑니다. 슬라이더를 움직이며 오른쪽 그래프의 점이 어디로 가는지 보세요.

NMS 먼저 적용 (IoU 0.5)
초록 = TP · 빨강 = FP · 빨간 점선 = 놓친 물체(FN) · 흰 점선 = 정답 상자
점 하나 = 임계값 하나(예측 상자의 신뢰도마다). 가로 = 재현율, 세로 = 정밀도. 노란 점 = 지금 임계값.
함정 · 확률이 높다고 맞는 것은 아니다숟가락은 모델이 배운 다섯 음식에 없는 물체입니다. 그래도 소프트맥스는 합이 1이 되도록 누군가에게 확률을 나눠 주어야 하므로 숟가락에 ‘김치 0.42’라는 상자 J가 생겼습니다. 임계값을 0.42 아래로 내리는 순간 J가 화면에 나타납니다. 신뢰도는 ‘정답일 확률’이 아니라 ‘보기 중에서 고른 비율’입니다.
토의 · 우리 급식 앱이라면
  • 알레르기 음식(예: 우유)을 알려 주는 앱이라면 정밀도와 재현율 중 무엇을 더 지켜야 할까요?
  • 잔반량을 재는 앱이라면 어떨까요? 임계값을 몇으로 정하고, 그 근거를 한 문장으로 써 봅시다.
